客户端使用说明

按实际使用路径编写：登录与绑定 → 老师端 → 学生端；每个界面写清入口、操作、前后模块关系，以及小笔 Agent 在该模块里的位置、输入和边界。

本文的目标态依据 小笔 Agent 架构（AGENT-ARCHITECTURE.md）；界面截图见主文档图 1–18。Agent 不是悬浮聊天框，而是贯穿五个模块的内核能力。

01启动与绑定笔

登录决定身份与 scope；绑定笔决定能看哪支笔的数据；两步都不经过 Agent。

图 3 · 登录

选身份并登录

老师/助教或学生由登录身份决定；登录后先调 /api/v1/me，拿角色、班级、笔绑定状态。没有笔绑定则进入绑定页；老师可「稍后再说」进入只读首页。

身份决定权限学生只看自己老师只看本班
图 4 · 绑定笔

输入 MAC/GUID 或扫码

输入笔身/包装上的 MAC 或 GUID；也可以点右上角「扫码绑笔」。绑定只写本地 pen_device/pen_binding，上游 app.user_pen 只读，不写回。绑定完成后才拉取套题、页和笔迹索引。

Agent 位置：本步骤没有 Agent 主体；绑定完成只提示「小笔可用」。未绑定数据不会被分析，也不会进入记忆。

上游只读绑定后才可分析不做身份反推

02老师端：标注 → 班级 → 套题 → 资料 → 笔迹 → 课堂

老师的 Agent 不是替代判断，而是把「老师标准 + 班级证据」组织成可复核的建议。

图 5 · 标注数据

先选套题与页

标注数据列出老师手里的套题和页；一套题显示页数、符号数、已标进度。点套题或页进入标注中心。这里是「老师标准」的入口。

模块交接：标注数据 → 标注中心；标注结果后面作为推理的 required_mark 证据，不是推理的替代品。

图 6 · 标注中心

画老师标准并保存

左侧选符号/接地文本和「只画未标注」；中间在讲义上画横线、圈、勾、叉；右侧选含义、原因、去向和「必标/可选/易错/个人」，完成后保存。顶部可切页、看未保存状态。

Agent 位置：标注中心不调用生成式 Agent；它产出「事实标准」。Agent 只能在后续推理/讲评中引用已保存的必勾，不能替老师改标准。

可追溯必标/可选分离Agent 只读引用
图 7 · 小笔 AI

带上下文提问，不自动下结论

从侧栏或模块内「问问小笔」打开右侧抽屉；顶部显示当前上下文 chips（套题 · 页 · 题 · 角色 · 记忆条数），可清除/切换。输入问题，Enter 发送，Shift+Enter 换行；可取消/打断。

Agent 形态：chat.graph + TurnLoop；工具包括笔迹、题目、老师必勾、记忆；返回 text/reasoning/tool/evidence/UI/approval，未知 UI 回退纯文本。

⌘KSSE可打断证据引用
图 8 · 班级汇总

先看全班，再点套题/学生

看 32 个学生、5 套题、解析覆盖率、需要关注 6 人；右侧班级小结/高频错因/没跑名单。点套题进入套题学生板；点学生进入逐题。

Agent 位置：teacher.graph 做班级聚合与错因聚类；只读班级 scope，不显示学生私有记忆原文；建议是「候选」，不自动发布。

图 9 · 套题学生

一套题下的 32 张学生卡

按覆盖/状态/错因筛选；点卡片进入学生逐题；右侧可看讲评包、提醒没跑的人。顶部可导出、提醒。

模块交接：班级汇总 → 套题学生 → 学生逐题；三者都围绕同一套题，不跳层。老师侧 Agent 可解释差异，但不评人。

图 10 · 资料室

套题、考点、讲评包

看 AI 建议下节课用哪套、哪个考点、什么讲评包；点套题看资产；点「新建讲评包」生成草稿。

Agent 位置：content.graph 先取证据再列大纲/草稿；生成后必须老师审核（采纳/编辑/删除/重生成），未审核不发布。

有依据草稿HITL 审核
图 11 · 笔迹中心

学生 × 套题矩阵

看谁写了哪套、差异多少、谁未绑笔；右侧是最近提交和差异待核对。点学生或「对比」进入标注差异。

Agent 位置：笔迹中心本身不生成结论；Agent 可按需解释某一页的差异，但证据必须来自笔迹/标注，不允许读他人数据。

图 12 · 标注差异

学生笔迹 vs 老师标准

左学生（红）、右老师（绿）同坐标双画布；顶部切「对照明细/双画布/时间分析/助教面板」，可切页、切学生。命中/漏标/错标分别看。

Agent 位置：可在差异页「问小笔」，输入是这一页/这个学生的证据；输出解释与引用，不评价学生能力。教师复核是 HITL。

图 13 · 课堂首页

开始上课前的检查

看下一节时间、学生笔就绪数、讲义标注页数、投屏状态；点「开始上课」进课堂；历史课堂可进复盘。

Agent 位置：课前不生成课堂结论；只做检查与提示。课堂副驾只在进入课堂后启动。

图 14 · 上课中

左工具、中画布、右学生状态

切题、画笔/高亮、投屏、完成本题；右栏看学生状态和 AI 提示。AI 提示最多 1 条主提示 + 2 条候选，老师「采纳」后才投屏，未采纳不投屏。

Agent 位置：classroom.graph 消费课堂事件；实时先本地绘制，统计 1–2s 聚合；AI 提示目标 <2s，超时显示「暂无提示」。不自动发通知、不改课件、不显示未提交姓名到投屏。

低延迟HITL 采纳投屏匿名

03学生端：只看自己的数据

图 15 · 我的套题

从自己的套题进入

学生看到自己写过的套题、47 页、132 题和解析进度；点套题进选页。没有班级、他人或教师数据入口。

图 16 · 选择一页

选页后进入逐题

页卡显示页号、题数、已解析/未解析；点页进入推理中心。页是标注/推理/笔迹的共同单位。

图 17 · 学生笔迹中心

看自己的页与回放

按时间看自己的页、完成情况、回放；可带着当前页问小笔。不能看他人笔迹。

图 18 · 学生资料室

只看发给自己的资料

学生只看自己的套题与讲评资产；教师备课本、班级聚合不进入学生端。

学生推理面板（图 15/16 的下一层）：未运行 → 点「问问小笔」→ 运行中（步骤+取消）→ 已解析（判断/依据/缺什么/证据）→ 可重跑/取消。未跑不显示假结论；取消不写结论、不占次数；重跑不覆盖旧版本。

04模块 × Agent 交互

同一内核、不同 manifest；入口在 L4，编排在 L3，能力在 L2/L1。客户端不直连 Agent。

五条关键交互链

1. 登录 → 绑定 → 首页
客户端 → report-server /me、/pen/* → 本地 PG；不经过 Agent。绑定成功才建立 data scope。
2. 标注 → 推理
标注中心保存老师标准 → 推理 run 读取 required_mark/题目/笔迹 → reasoning.graph 生成报告 → 后端 PG 写 reasoning_run/report；Agent 不直接写业务表。
3. 推理 → 资料 → 课堂
已跑报告/班级聚合 → 讲评包草稿（老师 HITL）→ 课堂首页/上课中；课堂只消费已审核内容。
4. 课堂事件 → 副驾 → 投屏
课堂事件流 → classroom.graph 提示候选 → 老师采纳 → 投屏；未采纳不投屏，投屏匿名。
5. 会话 → 记忆 → dreaming
agent_event 只追加 → 离线 dreaming 输出独立 store → 审阅/合并；请求路径只读注入 ≤900 tok；学生可纠正/忘记。

05记忆、dreaming 与 Agent 边界

四层记忆

transcript 事实层只追加；notes 记忆层存 node/edge/candidate；wiki 是离线可重建的表示；注入层每轮 ≤900 tok，只读装配。检索先过滤 tenant/student/status，再按 confidence/recency/importance 排序，PPR 后置。

dreaming 不在请求路径

会话结束/每日批/手动触发；pending→running→completed/failed/canceled；输入 store + sessions → 输出 store；默认不合并。单次 9.6–18.8s，所以不放在线；不生成学生结论、不碰教师数据。

Agent 的硬边界

report-server 拥有身份/scope/业务表/run 状态；agent-server 只做生成/证据/记忆/插件运行；客户端不直连 Agent/模型/数据库；教师动作 HITL；学生只看自己；不自动发布、不改分、不开放 shell。

06当前可用范围

按界面能走通的路径；没有的写清楚，不把目标态当现状。

可以走通：登录、绑定笔（含扫码）、标注数据/标注中心、小笔 AI、班级汇总、套题学生、资料室、笔迹中心、标注差异、课堂首页/上课中、学生端套题/选页/笔迹/资料。

当前未接：真实 SSO/组织同步、page_id 全量、symbol-service、content-pipeline、classroom-gateway :18121、生产 k8s/告警；这些在图 1 用虚线标为设计/未接。

使用顺序建议：先按「登录 → 绑定 → 标注 → 班级 → 套题 → 学生 → 课堂」走一遍；每一步确认角色、scope、证据和 HITL，再扩到真实数据。
